# reface CS/DX v1.30: FUNCTION menu, parameter system and LCD — RE notes

Findings from static disassembly (capstone, big-endian Thumb-1, link base
0x02020000) and behavioral verification (unicorn emulation of the patched and
unpatched image).  Everything below was checked against the actual v1.30
image regenerated by `tools/make_updaters.sh`.  Companion documents:
[README.md](README.md) (overview, updater format, clock sender), the
[MIDI 2 page patch](#the-midi-2-page-patch) at the bottom, and
[CHECKLIST.md](CHECKLIST.md) for hardware procedure.

Address conventions: "file 0x..." is an offset into
`out/reface_csdx_main_v130.bin` (1,966,080 bytes); bare 0x02xxxxxx/0x04xxxxxx
are runtime addresses.  ROM = flash alias at 0x02020000, RAM = the 0x0401xxxx
shared block.

## 1. Memory map relevant to the UI

| range | meaning |
|---|---|
| 0x02020000–0x0204FFFF | Thumb code (this image) |
| 0x0209xxxx–0x020CFFFF | ROM tables: LCD bitmaps, label lists, page records, parameter-group table |
| 0x0215C9B8–0x0215E0A0 | ROM master screen block, copied to RAM at boot (see §4) |
| 0x02160000+ (file 0x140000) | 0xFF erase fill — free space used by our patch |
| 0x04010000–0x040116E8 | shared RAM: mailbox at +0, screen records/lists at +0x1020 |
| 0x041480A0 | **system settings block, 32 bytes** (§2) |
| 0x041480C4 | voice-common shadow (150 bytes) |
| 0x0414815C | UI state / parameter group 0x0080 buffer (44 bytes, §5) |
| 0x0411216C | master UI state M (current group ctx, current record, §5) |

The boot copy is driven by a descriptor table in the reset area at file
0x6D8: `{fn 0x020216AD, src 0x0215C9B8, dst 0x04010000, end 0x040116E8}` —
5,864 bytes copied verbatim, so within that block **RAM address = ROM
address − 0x1084**.  The mailbox at 0x04010000 (`write 0xFF, wait for it to
change`) talks to the panel-scan Cortex-M3 (`sys_scanmicom.c`).

## 2. Settings and the parameter system

### 2.1 The settings block

`0x041480A0`, 32 bytes, **byte offset == SysEx system-parameter address**
(proven: every FUNCTION value draw reads `[0x041480A0 + param]` directly,
e.g. MIDI page value draw 0x02047D8C reads +0, +1, +0x0E, +0x06).

Ground truth from the Data List (references/reface_en_dl_b0.pdf):

| addr | DX meaning | CS meaning |
|---|---|---|
| 00 / 01 | TX / RX channel | same |
| 02–05 | master tune | same |
| 06 | local control | same |
| 07 | transpose | same |
| 08–09 | tempo (MSB/LSB) | same |
| 0A | LCD contrast | reserved |
| 0B | sustain pedal type | same |
| 0C | auto power-off | same |
| 0D | speaker output | same |
| 0E | MIDI control | same |
| 0F–1F | reserved | 0F = pitch-bend range, 14 = foot/sustain switch, rest reserved |

Because 0x15 is reserved on **both** models, it is the byte used by the
MIDI-clock switch.  The unified CS/DX binary shares one block layout, so a
byte documented as used by either model must be avoided.

### 2.2 Parameter group table (ROM 0x020C2120)

20-byte records, stride 0x14, iterated by the boot-time registrar
0x020425F0 (terminator: record with `+0xC == 0`):

```
+0x00 be32  base SysEx address of the group
+0x04 u8    kind (2 = SysEx-mappable)
+0x05 u8    element count
+0x06 s16   element size
+0x08 be32  per-parameter entries table
+0x0C be32  RAM buffer
+0x10 be32  stride/total
```

| record | base | cnt | size | entries | RAM buf |
|---|---|---|---|---|---|
| 0 | 00 30 00 00 (VOICE COMMON) | 1 | 0x26 | 0x020B7494 | 0x041480C4 |
| 1 | 00 31 00 00 (VOICE OPERATOR) | 4 | 0x1C | 0x020B7264 | 0x041480EA |
| 2 | **00 00 00 00 (SYSTEM)** | 1 | **0x20** | **0x020B6FE4** | **0x041480A0** |
| 3 | 00 78 40 00 (internal) | 1 | 0x10 | 0x020B6EA4 | 0x04148090 |
| 4 | 00 80 00 00 (UI group) | 1 | 0x2C | 0x020B6B34 | 0x0414815C |

`0x02042EEC(base, count, size, entries, buf, stride)` registers each group at
runtime; `0x02042E2C(addr)` finds the registration; the SysEx read/write
worker 0x020431BC computes `storage = buf + (addr − base)·stride` and memcpys
— **no per-entry validation**, so all 32 SYSTEM addresses 00–1F are readable
and writable through the parameter engine.

The SYSTEM entries table at 0x020B6FE4 (32 be32 words) is mostly zero; the
nonzero words (params 00, 03, 06, 08, 0B, 0D, 0E, 12, 13, 17, 18, 1C, 1D, 1F)
look like per-param maxima/format hints.  Zero-entry params are fully
functional: 01 (RX ch), 0A (contrast), 0C (auto power-off) all have zero
entries and are menu-settable.  Param 0x15 has a zero entry.

### 2.3 Setter chain

```
0x0204564C(param_addr, op, value)      op 1 = absolute set (page handlers)
  -> 0x02045544                         argument shuffle + stack descriptor
    -> 0x020436FC                       engine: find group, clamp, copy,
                                        run post-set hooks (redraw, MIDI
                                        transmit-on-change, dirty flags)
```

Page key handlers call it as `0x0204564C(0x00000E, 1, v)` etc.  The generic
panel-switch edit path 0x02044B78 calls it with op=2 and a param address
assembled from the focused layout row (§6.3) — but only for layout rows
whose type byte is 1 or 3 (numeric); **type-4 switches are toggled by key
events instead**.

## 3. FUNCTION pages

### 3.1 Data structures

Five pages, v1.30 numbering (per the Supplementary Manual p.13: page 2 =
Tuning "added", MIDI/System/Job moved to 3/4/5):

| page | content | ROM record | key handler | static draw | value draw | layout | label list |
|---|---|---|---|---|---|---|---|
| 0 | Voice parameter | 0x13D9D8 | 0x02046198 | 0x020479C0 | 0x020479D4 | 0x020C40D8 | pool+0x70 |
| 1 | Tuning (M.TUNE/M.TP) | 0x13D9EC | 0x020462E4 | 0x02047CB4 | 0x02047CD8 | 0x020C4118 | pool+0x30 |
| 2 | MIDI | 0x13DA00 | 0x02046130 | 0x02047D68 | 0x02047D8C | 0x020C4158 | pool+0x20 |
| 3 | System | 0x13DA14 | 0x020461F4 | 0x02047DC4 | 0x02047DEC* | 0x020C4198 | pool+0x60 |
| 4 | Job | 0x13DA28 | (0x02045E9C†) | 0x02047E3C | 0x02047E60* | 0x020C41D8 | pool+0x60? |

\* adjacent, from record words. † the page-4 record's key handler is
0x02047305 by record; 0x02045E9C is the handler that sets the page param to 4
on entry.

Page record (20 bytes):

```
+0x00 u8    column count (4 for all stock pages; also clamps the cursor)
+0x01 3 pad
+0x04 be32  layout table
+0x08 be32  key handler (Thumb bit set)
+0x0C be32  static draw
+0x10 be32  value draw
```

Group descriptor (8 bytes), ROM 0x13DA3C → RAM 0x04011084:

```
+0 u8  page count (5)
+1 u8  current page (runtime state — written by 0x0204639C event 1)
+2 u16 pad
+4 be32 record list (0x04011020, the five records above)
```

The records land at RAM 0x04011020..0x04011083 through the boot copy
(ROM − 0x1084).  **The firmware mutates the RAM records at runtime**:
0x0204636C (FUNCTION-enter bookkeeping) rewrites record 0's layout pointer
(RAM 0x04011024) to 0x020C4098 or 0x020C40D8 depending on
`[0x041480C4+0xD]` — a CS/DX model switch of page 0's layout.  The stock ROM
value is 0x020C40D8.

### 3.2 Page activation (proven by emulation)

`0x02044D84(desc)` stores the group descriptor into `M[0xC]`
(M = 0x0411216C, set by the FUNCTION-enter path with RAM 0x04011084).

`0x020448CC` "apply current screen/page", with M state annotated:

```
r2 = M[3]            target group slot within the context table at M[0xC]
r1 = M[6]            applied slot;  if equal -> item-level refresh only
M[6] = M[3]; M[7] = 0xFF
entry = M[0xC] + M[3]*8          ; 8-byte context entries
list  = [entry + 4]              ; the group descriptor's list field
page  = M[4]
record = list + page*0x14
M[0x10] = entry ; M[0x14] = record
if record.key: record.key(0,0,0)     ; "page became active" event 0
redraw (0x02045A2C: static+value draws via M[0x14]), key guide (0x02044848)
```

Emulating 0x020448CC with M[0xC]=0x04011084, M[4]=2 lands M[0x14] at exactly
the MIDI page record and calls 0x02046130 (verified with unicorn before and
after patching; see §8).  This is the mechanism the patch rides on.

### 3.3 Page selection — who moves the page

* `0x02044B60(page)` — writes `[0x0414815C+5]` then refreshes.  Only two
  callers: 0x02044B78 and 0x02044BD0.
* `0x02044BD0(key_id)` — `page = id − 0x12`; reached from the master
  dispatcher's event-8 branch (0x02044D50) for micom key ids
  **0x12–0x15 → pages 0–3**.  These are the "quick access" keys: the event
  is *also* forwarded as event 3 to the (new) current page's key handler,
  which toggles the corresponding column item — FUNCTION+key-0x14 jumps to
  the MIDI page *and* flips MIDI Control, etc.
* `0x02044B78(event)` — event 9 ("page change"): page = `[event+2]`.
* Param **0x00800005**: the page index *is* a parameter — the 0x0080 group's
  RAM buffer is 0x0414815C, so param 5 == `[0x0414815C+5]`.  Every page's key
  handler re-asserts its own page through `0x0204564C(0x00800005, 1, own)`
  on event 1.
* Cursor keys: ids 0x0B/0x10 → 0x02044B1C (moves the item focus, mode
  dependent).

**Not found anywhere in the main image**: an increment-and-wrap of the page
(searched every `[rX,#5]` load + `adds #1` site — zero hits).  The Owner's
Manual says repeated FUNCTION presses cycle pages, so the cycling either
arrives as event 9 with a page computed elsewhere (panel MCU?) or through a
path we did not locate.  Open question; the patch does not depend on it
(reachability comes from the extended quick-key range, §7).

### 3.4 Master event flow

```
panel MCU -> mailbox/ring -> micom pump 0x02047304(msg, data)
  msg > 0x0E : forward to master dispatcher 0x02044CB4(event, data)
  msg <= 0x0E: jump table at ROM 0x020C4750 (15 cases; FUNCTION enter/exit,
               hold timers, DATA ENTRY keys 0x0C/0x12)
0x02044CB4: current page's key handler gets event 2 first, then event 8 is
  decoded ([evt]==2 press, [evt+1]=id), then event 3 is forwarded.
```

Screen-mode handler table (10 Thumb fns) at ROM 0x020C3C64; slot 6 is the
FUNCTION-group dispatcher **0x0204639C** (events: 1 enter / 2 screen-switch /
5 timer / 0xF leave), slot 7 = 0x02046524 for the second group
({2, 0x0401108C}, records from ROM 0x13DA44).

## 4. Layouts

One 16-byte row per column, 4 columns:

```
+0 u8 addr_hi \  24-bit SysEx parameter address of the item
+1 u8 addr_mid|  (00 00 0E = MIDI Control, 00 00 06 = Local, ...)
+2 u8 addr_lo /
+3 u8 pad
+4 u8 type      1 = numeric (channel), 4 = on/off switch; 0x83 in addr
                bytes = empty column
+5.. pad
```

* Focus resolution: 0x0204457C — clamps cursor to `record[0]-1`, stores the
  focused row at `[0x0414815C+0x18]`; 0x02044C34 returns the focused type.
* Numeric edit: 0x02044B78 — builds the param address from row bytes 0–2,
  calls the setter with op=2 (types 1/3 only).
* The SYSTEM page uses `{00 83 83 00 04}` rows for its two "button" columns
  (EDIT RECALL / VOICE INIT style Job entries use 0x83 rows as well).

MIDI page layout (0x020C4158) rows: `{0,0,0x00,·,1} {0,0,0x01,·,1} {0,0,0x0E,·,4}
{0,0,0x06,·,4}` — TX ch, RX ch, CONTROL, LOCAL.

## 5. UI state structs

M = 0x0411216C (master): +3 target slot, +4 page-in-group, +6 applied slot,
+7/+8 item cursor state, +0xC group-context pointer (set by 0x02044D84),
+0x10 applied entry, +0x14 current page record pointer.

S = 0x0414815C (== 0x0080-group buffer, 44 bytes): +5 current page
(= param 0x00800005), +0xD model/link flag read by draws, +0x14 current
record (mirror used by refresh 0x0204479C), +0x18 focused layout row.

Refresh after a toggle: `0x0204479C` → draws `[M/S+0x14]+0xC` (static) and
`+0x10` (value) of the current record.

## 6. LCD drawing

1bpp framebuffer, blit `0x020291E8(rect_struct, bitmap)`; bitmaps are
**1bpp, row-major, MSB-first** (32px wide = 4 bytes/row).

| helper | args | what it draws |
|---|---|---|
| 0x0203C86C | (x, y, page) | page title icon 32×32: table base 0x020A494C, bitmap = [base+0x24+4·page]; titles 0–4 in use (2 = MIDI page icon) |
| 0x0203C254 | (list) | label list: 16-byte records `{s16 x, y, w, h; be32 bmp}`; terminator = record with byte[8]==0xFF |
| 0x0203C434 | (x, y, v) | on/off switch 32×32 at y=0x26: v==0 → "OFF" (0x020B08A8), v≠0 → "ON" (0x020B0840) |
| 0x0203C8E4 | (x, y, byte) | numeric value box (channel digits) |
| 0x02045B30 | (lamp_id, sel) | panel lamp / key-guide strip (8 guide ids 03–0A, ROM struct 0x020C3C44) |

Label-list pool at 0x020C4B30; the stock pages' lists live at +0x20 (MIDI),
+0x30, +0x60, +0x70.  Decoded stock labels (32×52, text at rows 10–31,
1px left rule):

```
0x020AB418  "CONTROL"     (MIDI page, column 2 / x=0x40)
0x020AC300  "LOCAL"       (MIDI page, column 3 / x=0x60)
0x020AC0F8  packed 64×52  (columns 0+1: TX/RX channel labels, second
                           item's left rule at bitmap x=31)
```

Values are drawn at y=0x26, one 32px cell per column (x = 0x00/0x20/0x40/0x60).

## 7. The MIDI clock path (recap)

Clock sender 0x02041438 (accumulator, one 0xF8 per 20 ticks); its only
caller is 0x020415B8:

```
020415b8  push {lr}
020415ba  sub  sp,#0xc
020415bc  str  r0,[sp,#4]
020415be  bl   0x2040428        ; sync-mode getter (0 = internal clock)
020415c2  cmp  r0,#0
020415c4  bne  0x20415e0        ; following external clock: other path
020415c6  ldr  r0,[sp,#4]
020415c8  bl   0x2041438        ; <- gate site (patch target)
...
```

## 8. The MIDI 2 page patch

`tools/patch_clock_menu.py` adds page 6 "MIDI 2" with one on/off item,
CLOCK, bound to settings byte 0x15.  Semantics: **0 = clock off, 1 = on,
anything else treated as on and normalised to 1 when the page is first
opened** (erased-flash 0xFF keeps stock behaviour: clock on).

New code/data in free ROM at 0x02160000 (file 0x140000), placed in order:
CLOCK label bitmap (32×52 1bpp, "CLOC"/"K" in the stock font style with the
left rule), label list, layout (row `{0,0,0x15,·,4}` + three 0x83 rows),
key handler, static draw (MIDI title icon + our label list), value draw
(on/off icon from the flag), 6-record page list (five stock records + ours),
clock trampoline.  All functions are assembled by a small big-endian
Thumb-1 assembler in the script (push/pop, movs, ldr-literal, ldrb, cmp,
b±cond, bl, bx) and verified by disassembly.

In-place patches (3 sites, 12 bytes):

| file offset | stock | patched | effect |
|---|---|---|---|
| 0x13DA3C | `{05, 0, 0, 0, 0x04011020}` | `{06, 0, 0, 0, <new list>}` | FUNCTION group has 6 pages, records read from the new list (boot-copied to RAM 0x04011084 exactly as before) |
| 0x24D72 | `2B03` (cmp r3,#3) | `2B05` (cmp r3,#5) | quick-key ids 0x16→page 4, **0x17→page 5** |
| 0x215C8 | `bl 0x02041438` | `bl trampoline` | clock send gated on settings[0x15] |

New page record: `{01 (one column), layout, key, static, value}`.  Key
handler: event 1 normalises the flag (not 0/1 → set 1) then asserts page
param 5; event 3 with `[evt]==2, [evt+1]==0x17` toggles
`0x0204564C(0x00000015, 1, new)` + refresh, exactly like the stock MIDI page
does for 0x0E/0x06.  Trampoline: `bx lr` when the flag is 0, else
`push {lr}; bl 0x02041438; pop {r3}; bx r3` (r0 tick argument preserved —
the caller never reads r0/r3 after the call).

### Verification (all automated, unicorn + capstone)

* trampoline: flag 0 → sender not executed; 1/2/0xFF → executed; r0 preserved
* value draw: flag 0 → OFF icon arg; 1/0xFF → ON icon arg
* key handler ev3: setter called with (0x00000015, 1, toggle); id 0x12 ignored
* key handler ev1: `(0x00800005, 1, 5)` always; `(0x15, 1, 1)` first when the
  stored flag is invalid
* page-apply 0x020448CC with the patched (RAM-copied) descriptor and
  M[4]=5: lands on our record and enters our key handler
* boot-copy math: patched descriptor lands at exactly RAM 0x04011084

### Known limitations / open questions

* **Which physical key sends id 0x17** in FUNCTION mode was not traced
  (key-id translation happens through per-key ramp tables around file
  0x6CE00–0x6DA00; ids 0x0A–0x1F all appear reachable).  On-hardware test
  needed; FUNCTION-button cycling may also reach page 6 if it honours the
  count byte (count consumer not identified — see §3.3).
* **Persistence of byte 0x15**: the SYSTEM group covers all 32 bytes, and
  the Data List's "SYSTEM Common 36 (0x24)" bulk size matches 32 data bytes
  + header, so SysEx dump/restore carries it.  The flash settings save was
  not fully traced; the previous agent's session verified "the 32-byte
  settings block persists through full saves/loads".  Confirm on hardware by
  power-cycling after a toggle.
* **CS caveat**: the runtime page-0 layout swap (§3.1) writes the *RAM*
  record list, which the patched descriptor no longer references; on a CS
  the page-0 layout would stay 0x020C40D8.  This firmware build targets the
  DX (the patch tool asserts the DX landmarks).
* Panel DATA ENTRY switch editing of the type-4 item (op=2 path) is not
  wired for switches in stock firmware; the intended interaction is the
  quick key (0x17) or the page toggle itself.
